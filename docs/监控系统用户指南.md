# Steam游戏更新监控系统 - 使用指南

## 📋 系统简介

本系统用于监控游戏更新后玩家评论的情绪、话题和风险，帮助您及时发现问题并采取行动。

---

## 🚀 快速开始（3步）

### 第1步：运行监控分析
```bash
python batch_inference.py --game_id 413150 --update_date 2024-03-20
```

**参数说明：**
- `game_id`: 游戏ID（例如：413150是《Rust》）
- `update_date`: 更新发布日期（格式：年-月-日）

**输出：** 系统会分析更新后48小时内的所有评论

---

### 第2步：查看可视化报告
```bash
python update_monitoring_dashboard.py --update_date 2024-03-20
```

**生成的报告位置：**
```
analysis_results/dashboards/dashboard_fps_20240320_48h.html
```

**用浏览器打开HTML文件**，可以看到：
- 📊 情绪趋势图（正面/中性/负面百分比）
- 🎯 话题分布饼图（玩家最关心什么）
- ⚠️ 风险时间线（高危评论数量变化）
- 🔝 高风险评论Top 20

---

### 第3步：检查危机告警
```bash
python crisis_alert.py --update_date 2024-03-20
```

**查看告警报告：**
```
analysis_results/alerts/crisis_alert_fps_20240320.md
```

**告警级别说明：**
- 🔴 **严重**（CRITICAL）：需要立即处理
- 🟠 **高**（HIGH）：24小时内响应
- 🟡 **中**（MEDIUM）：密切关注
- 🟢 **低**（LOW）：正常情况

## 📊 如何解读报告

### 1. 情绪趋势图
- **绿色（正面）**：玩家满意度高
- **灰色（中性）**：一般反馈
- **红色（负面）**：玩家不满

**⚠️ 注意：** 如果负面情绪超过60%，系统会发出告警

---

### 2. 话题分布
显示玩家讨论最多的6个话题：

| 话题 | 说明 | 示例 |
|------|------|------|
| 🎮 **匹配问题** | 匹配系统、等待时间 | "排队10分钟还没匹配到" |
| 🚫 **作弊问题** | 外挂、反作弊系统 | "遇到太多外挂了" |
| 💰 **付费问题** | 价格、氪金、性价比 | "皮肤太贵了" |
| 🖥️ **界面问题** | UI设计、菜单操作 | "新界面太难用" |
| 🔧 **技术问题** | 崩溃、卡顿、BUG | "更新后一直闪退" |
| 👥 **多人游戏** | 联机体验、服务器 | "延迟太高" |

**⚠️ 注意：** 如果"付费问题"超过30%且情绪负面，需要特别关注

---

### 3. 风险评分（0-10分）

| 分数 | 风险等级 | 说明 | 建议 |
|------|---------|------|------|
| 0-1 | 低风险 | 正常评论 | 无需行动 |
| 1-1.5 | 中风险 | 轻微不满 | 关注即可 |
| 1.5-2.5 | 高风险 | 明显问题 | 准备应对方案 |
| 2.5+ | 严重风险 | 重大危机 | 立即处理 |

**风险评分考虑因素：**
- 情绪极端程度
- 话题敏感性（作弊、付费权重高）
- 评论点赞数（影响力）
- 评论者游戏时长（资深玩家权重高）

## 🚨 5种自动告警规则

系统会自动检测以下5种危机情况：

### 告警1：负面情绪激增 🟠 HIGH
- **触发条件：** 负面评论超过60%
- **对比基线：** 更新前7天平均水平
- **示例：** 更新前负面率30% → 更新后负面率65% ⚠️

### 告警2：严重风险集中 🔴 CRITICAL
- **触发条件：** 高危评论（≥2.5分）超过5%
- **示例：** 1000条评论中有60条高危 ⚠️

### 告警3：付费争议 🟡 MEDIUM
- **触发条件：** 付费话题超过30%且情绪负面
- **示例：** 新皮肤定价引发大量批评 ⚠️

### 告警4：讨论量异常 🟡 MEDIUM
- **触发条件：** 每日评论数超过基线3倍
- **对比基线：** 更新前7天平均
- **示例：** 平时每天100条 → 更新后每天400条 ⚠️

### 告警5：趋势+风险双重警报 🔴 CRITICAL
- **触发条件：** 同时出现趋势告警和高风险评论≥10条
- **说明：** 问题正在快速恶化
- **示例：** 情绪快速下滑+大量高危评论 ⚠️⚠️

## 💡 使用建议

### ✅ 最佳实践

1. **更新发布后立即运行**
   - 建议在更新后6小时、24小时、48小时各运行一次
   - 及时发现问题可以快速响应

2. **关注变化趋势**
   - 不只看绝对数值，更要看与更新前的对比
   - 例如：负面率从30%升至70%比维持在60%更危险

3. **优先处理严重告警**
   - 🔴 CRITICAL告警：立即通知团队
   - 🟠 HIGH告警：24小时内制定应对方案
   - 🟡 MEDIUM告警：密切监控，准备预案

4. **查看具体评论**
   - 打开 `*_high_risk.csv` 查看高危评论原文
   - 了解玩家具体不满点，而非只看统计数字

### ⚠️ 注意事项

1. **新更新没有历史数据**
   - 第一次运行某个更新时，部分对比功能可能无效
   - 需要积累7天基线数据后，对比才更准确

2. **小样本量不可靠**
   - 如果评论数少于100条，统计可能不准确
   - 建议至少等待12小时后再运行

3. **告警不等于危机**
   - 系统告警是预警，需要人工判断
   - 结合具体评论内容和业务背景综合决策

## 🆘 常见问题

### Q1: 运行报错"找不到模型文件"
**A:** 系统需要先训练模型。请联系技术团队完成模型训练。

### Q2: 生成的HTML文件打不开
**A:** 用Chrome、Edge等现代浏览器打开。如果双击无效，右键选择"打开方式"。

### Q3: 告警阈值能否调整？
**A:** 可以。修改 `config/update_events.json` 文件中的阈值设置。

### Q4: 能否分析其他时间段？
**A:** 可以。使用 `--window_hours` 参数：
```bash
python batch_inference.py --update_date 2024-03-20 --window_hours 72
```
（分析72小时内的数据）

### Q5: 如何导出Excel报告？
**A:** CSV文件可以直接用Excel打开：
- `*_high_risk.csv`：高危评论
- `*_top_risk.csv`：Top 20评论
