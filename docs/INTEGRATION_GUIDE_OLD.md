# 趋势异常分析与现有模型集成指南（课程版）

## 概述与策略选择

本指南以“方案二（深度集成，统一系统）”为主线，辅以方案一（对比实验）作为有效性证明，并保留方案三（多任务学习）作为探索性内容。本文在原有流程基础上整合了近期代码改动，主要包括：

- 特征工程（FE）层面新增非破坏性清洗标记（`is_removed_cleaning`）、`include_flagged` 控制及显式的预训练模型路径参数。
- 趋势/异常分析（TAA）模块已修改为只负责趋势特征提取与异常检测（TrendForecaster 中的训练/预测逻辑已移除）；默认窗口为 24/48/72 小时，且默认启用协同检测（coordinated detection）。

目标产出：端到端可运行的分析系统（特征→趋势/异常→下游训练/评估→报告/监控），并包含每个训练任务的 Baseline 与 Advanced 对比与评估。

适配的课程评分关注点：系统性、可复现性、实验设计与结论清晰度、可扩展性。

---

## 架构与数据流（已包含近期改动）

数据流（简化）：

原始评论数据 → 基础特征工程（文本/情感/作者/互动等，含非破坏性清洗标记） → 特征工件（保存于 `features` 根目录，按 genre 子目录） → 趋势特征提取（24/48/72 小时滚动、差分、加速度等） → 异常检测（IF/统计/协同，默认启用协同检测） → 统一特征矩阵（基础+趋势+异常） → 下游三大任务模型（情感/主题/风险）→ 综合报告/可视化/告警

系统组成与职责：
- 基础特征工程：输出结构化文本与行为特征，提供标准化字段和时间索引。
  - 实现细节（近期更新）：
    - 非破坏性清洗：清洗阶段会新增 `is_removed_cleaning` 列（1 表示被清洗标记），而不是在源数据中删除行；特征生成函数 `create_comprehensive_features(..., include_flagged)` 控制是否包含这些行。
    - 预训练模型加载：`GPUOptimizedFeatureEngineer` 支持 `preloaded_topic_pca_path` 与 `preloaded_embedding_kmeans_path`，优先加载显式路径并尝试 `pickle` 与 `joblib` 两种格式以提高兼容性。
- 趋势特征模块：在不同时间窗口生成滚动统计、差分、加速度、峰谷信号（默认窗口：24/48/72 小时）。
  - 实现细节（近期更新）：`TrendFeatureExtractor` 只负责特征计算与异常检测；训练/预测功能已从模块中移除，建议在外部脚本使用其输出进行模型训练。
- 异常检测模块：输出异常分数与标记（含协同刷评识别）。
  - 实现细节：默认启用协同检测，处理结果会合并 `is_coordinated` 列到增强输出，并在同目录输出 `{prefix}_coordinated_groups.json`（若检测到群组）。
- 统一特征矩阵：合并基础+趋势+异常为下游可训练输入，确保切分与特征生成流程不会引入未来信息泄露。

关键设计要点：时序切分、泄露隔离、特征稳定性、指标闭环（特征生成→训练→推理→报告）。

## 实施步骤（无代码版，包含近期实现注意事项）

1) 数据准备与对齐
- 明确时间戳字段，确保单一时区、无乱序；缺失时间通过前向填充或剔除处理。
- 固化基础特征字段名与类型（如情感分数、互动统计、主题分布、作者画像等）。

2) 趋势与异常特征构建
- 窗口配置：24h/48h/72h（默认）。
- 核心趋势特征：滚动均值/方差、短期差分、波动性、局部峰谷、负面占比、评论速率。
- 异常检测：Isolation Forest（主）、统计阈值（辅）、协同模式（默认启用）；输出异常分数与标记，并在增强型输出中包含 `is_coordinated` 列。
- 文件加载与优先级：`load_feature_dataframe_from_dir(output_dir, file_prefix, include_flagged=None)` 会优先查找 `_inclflagged` / `_exclflagged` 变体并返回实际使用的变体标记，避免手动查错。

3) 统一特征矩阵与安全切分
- 拼接：基础+趋势+异常→统一矩阵，空值统一填补策略。
- 时序切分：按时间先后划分训练/验证，避免相邻泄露；不使用随机拆分。可使用 `TimeSeriesSplit` 做跨时间段的交叉验证。

4) 模型训练（新增：Baseline + Advanced 要求）
- 总体要求：针对每个训练任务（情感/主题/风险/趋势告警），必须实现并评估两类模型：
  1) 基线模型（Baseline）：简单、可解释、训练快速，作为性能对照。例如：TF-IDF + Logistic Regression、浅层随机森林或基于规则的阈值模型。
  2) 高级模型（Advanced）：性能优先，例如 LightGBM、BERT/Transformer + 任务头或特征工程后的集成模型。

- 训练与评估规范（每个任务都必须包含）：
  - 时间切分策略：严格的时序拆分（例如前 80% 训练、后 20% 验证/测试），并采用 `TimeSeriesSplit` 估计时间稳定性。
  - 指标与判据：
    - 情感（多类）：Primary = Weighted F1；辅项为每类 F1、Macro-F1、Accuracy。
    - 主题（多类）：Primary = Weighted F1 或 Accuracy（视类别均衡程度）；同时提供混淆矩阵与每类召回率。
    - 风险（二类）：Primary = PR-AUC；同时报告 Recall@K（例如 top 5%）、Precision、F1、False Positive Rate。
    - 趋势告警（二类/多类）：Primary = F1 与告警提前量（lead time，平均提前小时数）；同时给出告警率与误报率分析。
    - 异常检测（无监督/半监督）：Primary = 在可标注样本上的 precision/recall；报告阈值选择曲线与每窗口误报率。
    - 协同检测（行为群体）：Primary = 抽样验证 precision@k 与（如可用）召回估计；并提供群体样本列表用于人工复核。

- Baseline vs Advanced 对比要求：
  - 为每个任务提交一张对比表，包含 Baseline 和 Advanced 的主要指标、训练时间、资源消耗（RAM/GPU 时间）与可解释性说明。
  - 若 Advanced 未显著优于 Baseline，应在报告中讨论可能原因并保留 Baseline 作为资源受限时的 fallback。 

- 可复现性：固定随机种子、记录训练数据切分/时间窗口、导出模型配置与使用的特征清单。

5) 推理与分析管线
- 顺序：趋势特征→异常检测→特征拼接→多任务推理→汇总指标→生成报告与可视化。
- 告警合成：风险=1 或 （趋势告警） 或 异常=1 或 协同=1 即触发综合告警标记；可根据任务阈值调整告警灵敏度与误报成本权衡。

6) 报告与展示
- 报告内容：样本规模、情感/主题/风险分布、平均置信度、异常统计、趋势告警率、关键示例。
- 可视化：情感随时间曲线、异常分布直方图、特征重要性TopN、Baseline vs Advanced 对比图表。

## 方案一：对比实验（有效性证明）

实验目的：量化“趋势+异常”带来的收益，支撑课程报告结论。

建议配置：
- Baseline：仅基础特征（Baseline 模型）。
- +Trend：基础 + 趋势特征。
- +Anomaly：基础 + 异常分数。
- Full：基础 + 趋势 + 异常（Advanced 模型上比较）。

切分策略与指标参考：同上（严格时序切分；情感 Weighted F1、主题 Weighted F1/Accuracy、风险 PR-AUC、趋势 F1）。

## 方案三：多任务学习（探索性结果）

目标：在共享文本表示（如 BERT）基础上，叠加趋势特征编码，统一预测情感/主题/风险/趋势告警。该部分为加分项，非必交。

实现建议与报告方式：同先前章节，强调资源与可复现性限制，提供结构图与少量实证结果。

## 评估与验收标准（更新）

必须达成：
- 完整数据流闭环（特征→趋势/异常→多模型→报告）。
- 每个训练任务提交 Baseline 与 Advanced 两套实施并在报告中对比性能与资源消耗。
- 至少一张“有/无趋势（和/或 异常）”的对比图与表。

可选加分：
- 协同刷评识别案例与可视化。
- 趋势提前量设置与告警阈值优化的小实验。

## 风险与预案（更新）

- 数据跨度不足：缩小窗口或增加外部数据；优先使用短窗特征与异常分数。
- 类别极不均衡：采用类权重/阈值调整/PR-AUC 指标。
- 训练资源有限：优先 Baseline 模型作为快速可复现选项；Advanced 模型在资源允许时使用。

## 最佳实践要点（Checklist，补充）

- 时序切分，避免任何形式的数据泄露。
- 固定随机种子与数据版本，确保可复现与可追溯。
- 记录特征清单与重要性，解释收益来自何处（如短窗差分、波动性）。
- 对每个训练任务同时保存 Baseline 与 Advanced 的训练记录、超参与评估结果。
